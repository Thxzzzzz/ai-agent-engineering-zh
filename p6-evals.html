P6 · 评测流水线

"改了一句提示词，到底是变好还是变坏？"——没有评测，这个问题只能靠感觉。这个项目给 P2 的分诊管线和 P1 的 agent 搭一条完整的评测流水线，最后接进 CI，让回归无处藏身。

约 150 分钟前置：P1、P2、第 13 章含 1 个分步动画、2 个交互练习、1 道小测
做完你能
  • 从真实失败出发做错误分析，把它们整理成失败模式和评测任务
  • 写代码 grader 和"一个失败模式一个"的二元 LLM 判官，并用人工标注检验判官（TPR / TNR）
  • 每个任务跑 k 次，区分 pass@k 与 pass^k，知道面向用户的系统该看哪个
  • 生成带基线对比的报告，并把回归集接进 CI 作为合并闸门

1 · 成品是什么

一个 evals/ 目录，加一条命令 bun evals/cli.ts。它读取任务集，对每个任务跑 k 次试验，先用代码判、再按需请判官判，输出报告和与基线的差异；在 CI 里，回归集没达标就不许合并。

6.2 代码 grader：能用代码判的都用代码判

确定性、免费、可复现。注意"字段缺失"必须算失败——这是最常见的 grader bug。


import type { Assertion, Failure } from '../types';

// 按 "a.b.0.c" 取值；路径不存在返回 undefined。
export function getPath(value: unknown, path: string): unknown {
  let cur: unknown = value;
  for (const key of path.split('.')) {
    if (cur === null || typeof cur !== 'object') return undefined;
    cur = (cur as Record<string, unknown>)[key];
  }
  return cur;
}

function show(v: unknown): string {
  return v === undefined ? '（缺失）' : JSON.stringify(v);
}

export function gradeAssertions(output: unknown, assertions: Assertion[]): Failure[] {
  const failures: Failure[] = [];
  for (const a of assertions) {
    const actual = getPath(output, a.path);
    const text = typeof actual === 'string' ? actual : JSON.stringify(actual ?? '');
    let ok: boolean;
    let want: string;
    if ('equals' in a) {
      ok = actual !== undefined && Bun.deepEquals(actual, a.equals);
      want = `等于 ${show(a.equals)}`;
    } else if ('oneOf' in a) {
      ok = a.oneOf.some((x) => Bun.deepEquals(actual, x));
      want = `属于 ${show(a.oneOf)}`;
    } else if ('includes' in a) {
      ok = actual !== undefined && text.includes(a.includes);
      want = `包含 "${a.includes}"`;
    } else if ('excludes' in a) {
      ok = actual !== undefined && !text.includes(a.excludes);
      want = `不包含 "${a.excludes}"`;
    } else {
      ok = actual !== undefined && new RegExp(a.matches).test(text);
      want = `匹配 /${a.matches}/`;
    }
    if (!ok) failures.push({ mode: `assert:${a.path}`, detail: `${a.path} 应${want}，实际 ${show(actual)}` });
  }
  return failures;
}

6.3 失败模式与二元判官

判官提示词的原料就是错误分析的产物：每个失败模式一个定义、一个通过的例子、一个失败的例子。几个刻意的设计：

  • 一个判官只查一种失败，不打 1–5 分。二元结论更稳定，也更容易和人工标注对齐。
  • 先摘证据再下结论：schema 里 evidence 排在 verdict 前面，让模型先找依据。
  • 允许 unknown：信息不足时说"判断不了"，比硬猜好。unknown 单独计数，交给人看。

// 失败模式来自错误分析（读真实 trace → 开放笔记 → 归类），不是凭空列出来的。
// 每个模式一个二元判官：只回答"这个失败有没有发生"。
export const FAILURE_MODES: Record<string, { title: string; definition: string; passExample: string; failExample: string }> = {
  unfounded_commitment: {
    title: '无依据的承诺',
    definition: '回复草稿承诺了具体的完成时间、结果或补偿，但工单内容和参考信息里都没有依据。',
    passExample: '"已收到，我们确认后今天内回复你处理方案。"（只承诺回复，不承诺结果）',
    failExample: '"这个问题明天上午一定修好。"（工单里没有任何人给出过这个时间）',
  },
  ignores_main_question: {
    title: '没回应主要问题',
    definition: '工单里有一个明确的问题或请求，回复草稿没有回应它，只给了泛泛的客套话。',
    passExample: '对方问"导出能按部门筛选吗"，草稿说明了能否筛选或何时答复。',
    failExample: '对方问"导出能按部门筛选吗"，草稿只说"感谢反馈，我们会持续改进"。',
  },
  claims_unperformed_action: {
    title: '声称做了没做的事',
    definition: '最终回答声称已经完成某个动作（已添加、已删除、已发送），但执行轨迹里没有对应的成功工具调用。',
    passExample: '轨迹里有 add_todo 成功的结果，回答说"已添加"。',
    failExample: '轨迹里 add_todo 返回错误，回答却说"已帮你添加"。',
  },
};


import { z } from 'zod';
import type { Model } from '../../src/model';
import { completeStructured } from '../../src/structured';
import { FAILURE_MODES } from '../failure-modes';
import type { EvalTask, JudgeFn, TargetRun } from '../types';

const JudgeSchema = z.strictObject({
  evidence: z.string().describe('从输出或轨迹里原样摘出的、支撑判断的片段；没有就写"无"'),
  verdict: z.enum(['pass', 'fail', 'unknown']).describe('pass = 该失败没有发生；fail = 发生了；unknown = 信息不足以判断'),
  reason: z.string().describe('一两句话说明判断依据'),
});

export function judgePrompt(mode: string): string {
  const m = FAILURE_MODES[mode];
  if (!m) throw new Error(`未定义的失败模式：${mode}`);
  return [
    '你是一名严格的评测员，只检查一种失败模式，不评价其他方面。',
    `失败模式：${m.title}`,
    `定义：${m.definition}`,
    `不算失败的例子：${m.passExample}`,
    `算失败的例子：${m.failExample}`,
    '先摘出证据，再下结论。证据不足以判断时选 unknown，不要猜。',
  ].join('\n');
}

export function createJudge(model: Model): JudgeFn {
  return async (mode: string, task: EvalTask, run: TargetRun) => {
    const user = [
      `## 任务输入\n${JSON.stringify(task.input, null, 2)}`,
      task.reference ? `## 参考答案\n${task.reference}` : '',
      `## 被评测的输出\n${JSON.stringify(run.output, null, 2)}`,
      `## 执行轨迹\n${run.transcript.slice(0, 12000)}`,
    ].filter(Boolean).join('\n\n');
    const { value } = await completeStructured(model, { schema: JudgeSchema, system: judgePrompt(mode), user });
    return { verdict: value.verdict, reason: `${value.reason}（证据：${value.evidence}）` };
  };
}

6.4 被评测对象：评结果，不评路径

agent 的同一个任务可以有多条正确路径（先列清单再添加，或者直接添加）。评测检查的是最终状态：清单里实际有什么、回答说了什么。每次试验都新建一份待办清单，保证试验互不污染。


import { z } from 'zod';
import { runAgent } from '../src/loop';
import type { Model } from '../src/model';
import { defineTool, type Tool } from '../src/tools';
import { analyzeTicket } from '../src/triage/pipeline';
import { loadPrompt } from '../src/triage/prompt';
import type { Ticket } from '../src/triage/schema';
import type { Target } from './types';

// P2 的分诊管线：输入是一张工单，输出是分诊结果加上路由。
// 日期固定下来，避免"今天"不同导致同一任务的期限判断漂移；提示词只加载一次，版本写进轨迹。
export function triageTarget(model: Model, today = '2026-11-30'): Target {
  const prompt = loadPrompt('triage');
  return async (input) => {
    const r = await analyzeTicket(model, input as Ticket, await prompt, today);
    if (!r.ok) throw new Error(r.error); // 结构化输出失败：记为这次试验出错
    const output = { ...r.analysis, route: r.route };
    return { output, transcript: `prompt=${r.prompt} attempts=${r.attempts}\n${JSON.stringify(output)}` };
  };
}

// P1 的 agent：每次试验都新建一份待办清单，试验之间互不影响（干净环境）。
// 评的是最终状态（清单里有什么）和回答，而不是它调用工具的路径。
export function createTodoEnv(seed: string[] = []) {
  const todos = seed.map((title, i) => ({ id: i + 1, title, done: false }));
  let nextId = todos.length + 1;
  const tools: Tool[] = [
    defineTool({
      name: 'list_todos',
      description: '列出全部待办，返回 JSON 数组。',
      schema: z.strictObject({}),
      run: async () => JSON.stringify(todos),
    }),
    defineTool({
      name: 'add_todo',
      description: '新增一条待办。标题不超过 50 字；已存在同名待办时返回错误。',
      schema: z.strictObject({ title: z.string().trim().min(1).max(50).describe('待办标题') }),
      run: async ({ title }) => {
        if (todos.some((t) => t.title === title)) throw new Error(`已存在同名待办：${title}`);
        todos.push({ id: nextId++, title, done: false });
        return `已添加 #${nextId - 1}`;
      },
    }),
    defineTool({
      name: 'complete_todo',
      description: '把指定 id 的待办标记为完成。',
      schema: z.strictObject({ id: z.number().int() }),
      run: async ({ id }) => {
        const t = todos.find((x) => x.id === id);
        if (!t) throw new Error('没有这个 id 的待办，请先 list_todos');
        t.done = true;
        return `已完成 #${t.id}`;
      },
    }),
  ];
  return { tools, state: () => ({ todos: structuredClone(todos) }) };
}

export function agentTarget(model: Model): Target {
  return async (input) => {
    const { prompt, seed } = input as { prompt: string; seed: string[] };
    const env = createTodoEnv(seed);
    const result = await runAgent(prompt, { model, tools: env.tools, system: '你是待办助手，只能通过工具读写待办。', maxSteps: 8 });
    const transcript = result.messages
      .map((m) =>
        m.role === 'assistant'
          ? `assistant: ${m.content} ${JSON.stringify(m.toolCalls)}`
          : m.role === 'tool'
            ? `tool${m.isError ? '(错误)' : ''}: ${m.content}`
            : `${m.role}: ${m.content}`,
      )
      .join('\n');
    return { output: { answer: result.text, ...env.state() }, transcript };
  };
}

6.5 runner：k 次试验、并发上限、错误隔离


import { gradeAssertions } from './graders/code';
import type { EvalTask, Failure, JudgeFn, Target, TrialResult, Verdict } from './types';

export type RunOptions = {
  k: number;                                   // 每个任务跑几次
  concurrency: number;                         // 同时在跑的试验上限（受限于模型的速率限制）
  targets: Record<EvalTask['target'], Target>;
  judge: JudgeFn | null;                       // null = 只跑代码 grader（快、免费）
  onProgress?: (done: number, total: number) => void;
};

// 简单的并发闸门：最多 limit 个任务同时执行。
async function mapLimit<T, R>(items: T[], limit: number, fn: (item: T) => Promise<R>): Promise<R[]> {
  const out: R[] = new Array(items.length);
  let next = 0;
  const workers = Array.from({ length: Math.min(limit, items.length) }, async () => {
    while (next < items.length) {
      const i = next++;
      out[i] = await fn(items[i]!);
    }
  });
  await Promise.all(workers);
  return out;
}

async function runTrial(task: EvalTask, trial: number, opts: RunOptions): Promise<TrialResult> {
  const started = performance.now();
  try {
    // 每次试验都调用 target 重新建环境，试验之间不共享任何状态。
    const run = await opts.targets[task.target](task.input);
    const failures: Failure[] = gradeAssertions(run.output, task.expect);
    let unknown = false;
    // 代码 grader 已经判失败时不再花钱问判官
    if (failures.length === 0 && opts.judge) {
      for (const mode of task.judge) {
        const j = await opts.judge(mode, task, run);
        if (j.verdict === 'fail') failures.push({ mode, detail: j.reason });
        if (j.verdict === 'unknown') unknown = true;
      }
    }
    const verdict: Verdict = failures.length ? 'fail' : unknown ? 'unknown' : 'pass';
    return { taskId: task.id, trial, verdict, failures, output: run.output, error: null, ms: performance.now() - started };
  } catch (e) {
    const message = e instanceof Error ? e.message : String(e);
    return {
      taskId: task.id, trial, verdict: 'fail', failures: [{ mode: 'error', detail: message }],
      output: null, error: message, ms: performance.now() - started,
    };
  }
}

export async function runEval(tasks: EvalTask[], opts: RunOptions): Promise<TrialResult[]> {
  const jobs = tasks.flatMap((task) => Array.from({ length: opts.k }, (_, trial) => ({ task, trial })));
  let done = 0;
  return mapLimit(jobs, opts.concurrency, async ({ task, trial }) => {
    const r = await runTrial(task, trial, opts);
    opts.onProgress?.(++done, jobs.length);
    return r;
  });
}

export async function loadTasks(path: string): Promise<EvalTask[]> {
  const text = await Bun.file(path).text();
  const tasks = text.split('\n').filter((l) => l.trim()).map((l, i) => {
    try {
      return JSON.parse(l) as EvalTask;
    } catch {
      throw new Error(`${path} 第 ${i + 1} 行不是合法 JSON`);
    }
  });
  const ids = new Set<string>();
  for (const t of tasks) {
    if (ids.has(t.id)) throw new Error(`任务 id 重复：${t.id}`);
    ids.add(t.id);
  }
  return tasks;
}

6.6 指标：pass@k 与 pass^k

同样跑 n 次、通过 c 次，两个指标回答的是不同的问题：

指标回答的问题适合
pass@kk 次里至少一次成功的概率有人从多个候选里挑结果的场景，如生成多份草稿让人选
pass^kk 次全部成功的概率面向用户、每次都必须对的场景。单次 75% 时，pass^3 只有约 42%

import type { TrialResult } from './types';

// 组合数 C(n, k)，用连乘避免阶乘溢出。
function comb(n: number, k: number): number {
  if (k < 0 || k > n) return 0;
  let r = 1;
  for (let i = 1; i <= k; i++) r = (r * (n - k + i)) / i;
  return r;
}

// n 次试验里 c 次通过时，"k 次里至少一次通过"的无偏估计。
export function passAtK(n: number, c: number, k: number): number {
  if (k > n) throw new Error(`k=${k} 不能大于试验次数 n=${n}`);
  return 1 - comb(n - c, k) / comb(n, k);
}

// "k 次全部通过"的估计：面向用户的 agent 更该看这个，用户每次都要它成功。
export function passHatK(n: number, c: number, k: number): number {
  if (k > n) throw new Error(`k=${k} 不能大于试验次数 n=${n}`);
  return comb(c, k) / comb(n, k);
}

export type TaskStat = { taskId: string; n: number; passed: number; unknown: number; rate: number };

export function taskStats(results: TrialResult[]): TaskStat[] {
  const by = new Map<string, TrialResult[]>();
  for (const r of results) by.set(r.taskId, [...(by.get(r.taskId) ?? []), r]);
  return [...by.entries()].map(([taskId, rs]) => {
    const passed = rs.filter((r) => r.verdict === 'pass').length;
    return { taskId, n: rs.length, passed, unknown: rs.filter((r) => r.verdict === 'unknown').length, rate: passed / rs.length };
  });
}

export function summarize(results: TrialResult[], k: number) {
  const stats = taskStats(results);
  const mean = (f: (s: TaskStat) => number) => (stats.length ? stats.reduce((a, s) => a + f(s), 0) / stats.length : 0);
  return {
    tasks: stats.length,
    passAt1: mean((s) => s.rate),
    passAtK: mean((s) => passAtK(s.n, s.passed, Math.min(k, s.n))),
    passHatK: mean((s) => passHatK(s.n, s.passed, Math.min(k, s.n))),
    unknownTrials: stats.reduce((a, s) => a + s.unknown, 0),
  };
}

export function failureCounts(results: TrialResult[]): Array<[string, number]> {
  const counts = new Map<string, number>();
  for (const r of results) for (const f of r.failures) counts.set(f.mode, (counts.get(f.mode) ?? 0) + 1);
  return [...counts.entries()].sort((a, b) => b[1] - a[1]);
}

6.7 报告与基线对比


import { failureCounts, summarize, taskStats } from './metrics';
import type { TrialResult } from './types';

export type Diff = { regressions: string[]; fixes: string[] };

// 与基线逐任务比较：以前每次都过、现在有失败 = 回归；以前有失败、现在每次都过 = 修复。
export function diffBaseline(current: TrialResult[], baseline: TrialResult[]): Diff {
  const before = new Map(taskStats(baseline).map((s) => [s.taskId, s.rate]));
  const regressions: string[] = [];
  const fixes: string[] = [];
  for (const s of taskStats(current)) {
    const b = before.get(s.taskId);
    if (b === undefined) continue;
    if (b === 1 && s.rate < 1) regressions.push(s.taskId);
    if (b < 1 && s.rate === 1) fixes.push(s.taskId);
  }
  return { regressions, fixes };
}

const pct = (x: number) => `${(x * 100).toFixed(1)}%`;

export function renderReport(results: TrialResult[], k: number, baseline: TrialResult[] | null): string {
  const s = summarize(results, k);
  const lines = [
    '# 评测报告',
    '',
    `| 任务数 | pass@1 | pass@${k} | pass^${k} | 判官无法判断的试验 |`,
    '|---|---|---|---|---|',
    `| ${s.tasks} | ${pct(s.passAt1)} | ${pct(s.passAtK)} | ${pct(s.passHatK)} | ${s.unknownTrials} |`,
    '',
    '## 失败模式',
    '',
    ...failureCounts(results).map(([mode, n]) => `- ${mode}：${n} 次`),
  ];
  if (baseline) {
    const b = summarize(baseline, k);
    const d = diffBaseline(results, baseline);
    lines.push(
      '',
      '## 与基线对比',
      '',
      `pass@1 ${pct(b.passAt1)} → ${pct(s.passAt1)}，pass^${k} ${pct(b.passHatK)} → ${pct(s.passHatK)}`,
      '',
      `回归（以前全过、现在有失败）：${d.regressions.join('、') || '无'}`,
      `修复（以前有失败、现在全过）：${d.fixes.join('、') || '无'}`,
    );
  }
  const failed = results.filter((r) => r.verdict !== 'pass');
  if (failed.length) {
    lines.push('', '## 失败明细（先读这些 transcript，再改提示词）', '');
    for (const r of failed.slice(0, 30)) lines.push(`- ${r.taskId}#${r.trial} [${r.verdict}] ${r.failures.map((f) => f.detail).join('；')}`);
  }
  return `${lines.join('\n')}\n`;
}

6.9 判官对齐

随机抽 100–200 条判官结果做人工标注（Hamel 与 Shreya 的建议量级），拆成调整用和检验用两份：调整判官提示词时只看前者，最后在后者上报告一致度，避免把判官"调"得只适合这批样本。


// 判官对齐：拿人工标注检验 LLM 判官靠不靠谱。
// 用法：bun evals/align.ts evals/labels.jsonl evals/judged.jsonl
// 两个文件每行 { "key": "任务id#试验#失败模式", "verdict": "pass" | "fail" | "unknown" }，前者是人标的，后者是判官给的。
type Row = { key: string; verdict: 'pass' | 'fail' | 'unknown' };

export function alignment(human: Row[], judge: Row[]) {
  const j = new Map(judge.map((r) => [r.key, r.verdict]));
  let tp = 0; // 人判通过，判官也判通过
  let fn = 0; // 人判通过，判官判失败
  let tn = 0; // 人判失败，判官也判失败
  let fp = 0; // 人判失败，判官判通过（最危险：放过了真问题）
  let unknown = 0;
  let missing = 0;
  for (const h of human) {
    if (h.verdict === 'unknown') continue;
    const v = j.get(h.key);
    if (v === undefined) missing++;
    else if (v === 'unknown') unknown++;
    else if (h.verdict === 'pass') v === 'pass' ? tp++ : fn++;
    else v === 'fail' ? tn++ : fp++;
  }
  return {
    tpr: tp + fn ? tp / (tp + fn) : Number.NaN, // 真通过里被判通过的比例
    tnr: tn + fp ? tn / (tn + fp) : Number.NaN, // 真失败里被判失败的比例
    confusion: { tp, fn, tn, fp },
    unknown,
    missing,
  };
}

async function readRows(path: string): Promise<Row[]> {
  return (await Bun.file(path).text()).split('\n').filter((l) => l.trim()).map((l) => JSON.parse(l) as Row);
}

if (import.meta.main) {
  const [humanPath, judgePath] = process.argv.slice(2);
  if (!humanPath || !judgePath) throw new Error('用法：bun evals/align.ts <人工标注.jsonl> <判官结果.jsonl>');
  const r = alignment(await readRows(humanPath), await readRows(judgePath));
  console.log(`TPR（真通过被判通过）${(r.tpr * 100).toFixed(1)}%  TNR（真失败被判失败）${(r.tnr * 100).toFixed(1)}%`);
  console.log(`混淆：${JSON.stringify(r.confusion)}  判官无法判断 ${r.unknown}  缺少判官结果 ${r.missing}`);

}

6.10 从 trace 一键生成候选任务

评测集要持续生长：每周把新的失败样本收进来。候选任务只填输入和来源，期望值必须由人补——期望值从需求推导，不从模型当时的输出里抄。


// 从线上 trace 挑出值得变成评测任务的样本：出错的、被用户拒绝或改写的。
// 用法：bun evals/from-traces.ts traces/*.jsonl > evals/candidates.jsonl
// trace 每行 { id, ts, target, input, output, error, feedback }，feedback 取 'approved' | 'edited' | 'rejected' | null。
import { createHash } from 'node:crypto';
import type { EvalTask } from './types';

type TraceLine = {
  id: string;
  ts: string;
  target: EvalTask['target'];
  input: unknown;
  output: unknown;
  error: string | null;
  feedback: 'approved' | 'edited' | 'rejected' | null;
};

export function pickCandidates(lines: TraceLine[], existingInputs: Set<string>): EvalTask[] {
  const seen = new Set(existingInputs);
  const out: EvalTask[] = [];
  for (const t of lines) {
    const interesting = t.error !== null || t.feedback === 'edited' || t.feedback === 'rejected';
    if (!interesting) continue;
    const fp = createHash('sha256').update(JSON.stringify(t.input)).digest('hex').slice(0, 16);
    if (seen.has(fp)) continue; // 同样的输入只收一次
    seen.add(fp);
    out.push({
      id: `${t.target}-${fp}`,
      suite: 'capability', // 先进能力集，修好并稳定通过后再"毕业"进回归集
      target: t.target,
      input: t.input,
      expect: [],          // 由人补上：期望的字段与判官要查的失败模式
      judge: [],
      reference: null,
      tags: [t.error ? 'error' : `feedback:${t.feedback}`],
      source: `trace:${t.id}`,
    });
  }
  return out;
}

export function inputFingerprint(input: unknown): string {
  return createHash('sha256').update(JSON.stringify(input)).digest('hex').slice(0, 16);
}

if (import.meta.main) {
  const files = process.argv.slice(2);
  const lines: TraceLine[] = [];
  for (const f of files) {
    for (const l of (await Bun.file(f).text()).split('\n')) if (l.trim()) lines.push(JSON.parse(l) as TraceLine);
  }
  const tasksFile = Bun.file('evals/tasks.jsonl');
  const existing = (await tasksFile.exists())
    ? new Set((await tasksFile.text()).split('\n').filter((l) => l.trim()).map((l) => inputFingerprint((JSON.parse(l) as EvalTask).input)))
    : new Set<string>();
  for (const c of pickCandidates(lines, existing)) console.log(JSON.stringify(c));
}

            missing_info: [],
            reply_draft: '收到，我先确认可行性，周五前答复你。',
            confidence: 0.8,
          }),
        ],
      },
    ]);
    const agentModel = new FakeModel([
      { toolCalls: [call('add_todo', { title: '交周报' })] },
      { content: '清单里已存在「交周报」，没有重复添加。' },
    ]);
    const [t] = await runEval([filter], { k: 1, concurrency: 1, targets: { triage: triageTarget(triageModel), agent: agentTarget(agentModel) }, judge: null });
    const [a] = await runEval([dup], { k: 1, concurrency: 1, targets: { triage: triageTarget(triageModel), agent: agentTarget(agentModel) }, judge: null });
    expect([t!.verdict, a!.verdict]).toEqual(['pass', 'pass']);
  });
});

新版提示词上线前跑评测：pass@1 从 86% 升到 88%，但回归集里 triage-invoice-wrong 从 5/5 掉到 3/5。应该怎么做？

  1. 总分上升了，直接上线
  2. 先读这个任务失败的 transcript，弄清是新提示词引入的问题还是任务本身有歧义，再决定
  3. 把这个任务从回归集删掉
  4. 把 k 调大到 10，平均下来就好了
回归集的任务以前稳定通过，现在掉了，就是信号。平均分会掩盖它。第一步永远是读 transcript：如果是提示词把"发票问题"误判成别的类别，就要修；如果发现任务本身的期望有歧义，修任务（并记录原因），而不是悄悄删掉。

8 · 验收标准

  • 完成一次错误分析：读过至少 30 条真实或模拟的 trace，写出 3 个以上有定义和例子的失败模式
  • tasks.jsonl 里至少 20 个任务，正例反例都有，区分回归集与能力集
  • bun test 通过，评测流水线本身的测试覆盖 grader、指标、runner、基线对比和对齐
  • 用真实模型跑一次 bun evals/cli.ts --k 3，生成报告并保存为基线
  • 人工标注至少 50 条判官结果，报告 TPR 与 TNR，并根据放过的失败改进过一次判官定义
  • 故意改坏提示词，CI 闸门能拦住；改回后通过
  • 从 trace 生成过一批候选任务，并人工补全期望后收进任务集

9 · 进阶挑战

  1. 给判官加"自一致性"检查：同一样本让判官判 3 次，结论不一致的样本自动进入人工复核队列。
  2. 记录每次试验的 token 用量与耗时，在报告里加"每个通过的任务花了多少钱"，比较两个模型的性价比。
  3. 给 agent 加一个"用户模拟器"：另一个模型扮演用户，在多轮对话里提出补充要求（参考 τ²-bench 的双控思路），评测多轮场景。
  4. 能力集的任务连续三次全过后，自动提出"毕业到回归集"的建议（由人确认）。
  5. 把报告做成静态网页：每个失败样本可以展开看完整 transcript，并直接标注人工结论写回 labels.jsonl。

10 · 常见坑

  • 先写指标、后看数据：拍脑袋的指标（"有用性 1–5 分"）测不出真实问题。先错误分析，再定失败模式。
  • 只跑一次：模型有随机性，一次通过不代表稳定。至少 k=3，面向用户的看 pass^k。
  • 评路径而不是结果：断言"必须先调用 list_todos"会误伤合理的其他路径。检查最终状态。
  • 判官没人校验：未经对齐的判官只是另一个不可靠的模型。
  • 通过率接近 0 的任务：多次试验都接近 0%，通常是任务本身坏了（期望写错、信息不足），不是 agent 不行。先查任务。
  • 期望值从输出里抄：那样测的是"和上次一样"，而不是"对不对"。
  • 试验共享环境：上一次的副作用会让下一次"意外通过"或"意外失败"。
本项目要点
  • 评测从真实失败开始：错误分析 → 失败模式 → 任务，20–50 个就能起步。
  • 代码 grader 优先；判官只做代码判不了的，一个失败模式一个，二元 + unknown。
  • 判官要用人工标注检验，最怕把真失败判成通过。
  • 每任务跑 k 次；面向用户的系统看 pass^k；逐任务与基线比，别被平均数骗。
  • 回归集接进 CI 作为闸门，能力集衡量进步；评测集随 trace 持续生长。
