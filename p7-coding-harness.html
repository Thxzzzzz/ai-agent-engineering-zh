P7 · 编码 Agent 驾驭器

编码 agent 已经很能干，但把它放进真实仓库跑几个小时，问题就变成了工程问题：在哪儿跑、能动什么、做到哪了、什么时候算完、跑偏了谁来拉回来。这个项目写一个小型"驾驭器"（harness）来回答这些问题。

约 150 分钟前置：第 10 章、第 12 章含 1 个分步动画、1 个控制台模拟、1 道小测
做完你能
  • 用 git worktree 给每个任务一个隔离的目录与分支，并安全地收尾清理
  • 以 headless 方式驱动编码 agent，解析它的事件流，记录进度与成本
  • 用 git 与 gh 的客观状态（提交、PR、CI）判断进度，而不是相信 agent 的自述
  • 用功能清单、进度文件、Stop hook 和独立复核，对付"上下文耗尽"和"过早宣布完成"两类典型失败
关于命令行参数

本页用 Claude Code 的 print 模式（claude -p）作为主示例，并给出 OpenAI Codex（codex exec）的替代写法。两者的参数、事件字段和权限规则语法都在快速演进，以各自官方文档为准，本页核对于 2026-11。驾驭器把与具体 agent 相关的部分集中在 harness/agent.ts 一个文件里，换 agent 只改这里。

import { z } from 'zod';

// 一个开发任务：由人写好，驾驭器只负责执行与核对，不替人改需求。
export const CodingTaskSchema = z.object({
  id: z.string().regex(/^[a-z0-9-]{3,40}$/, '只用小写字母、数字和连字符，3–40 位'),
  title: z.string().min(1),
  repo: z.string().min(1).describe('仓库主目录的绝对路径'),
  base: z.string().default('main'),
  agent: z.enum(['claude', 'codex']).default('claude'),
  acceptance: z.array(z.string().min(1)).min(1).describe('验收点，每条一句可验证的话'),
  verify: z.array(z.string()).min(1).describe('独立复核用的命令，如 ["bun", "test"]'),
  maxSessions: z.number().int().min(1).max(30).default(8),
  maxCostUsd: z.number().positive().default(5),
});
export type CodingTask = z.infer<typeof CodingTaskSchema>;

export async function loadTask(path: string): Promise<CodingTask> {
  const parsed = CodingTaskSchema.safeParse(await Bun.file(path).json());
  if (!parsed.success) throw new Error(`任务文件 ${path} 不合法：\n${z.prettifyError(parsed.error)}`);
  return parsed.data;
}

export function branchName(task: CodingTask): string {
  return `agent/${task.id}`;
}

6.2 命令执行与确认

需要人确认的步骤要求输入一个特定的词（任务 id、remove），而不是回车即过——习惯性回车是"走过场的审批"最常见的形态。


// 运行外部命令。所有 git / gh / agent 调用都经这里，统一拿到退出码与输出。
export type ShResult = { code: number; stdout: string; stderr: string };

export async function sh(cmd: string[], cwd: string, opts: { timeoutMs?: number } = {}): Promise<ShResult> {
  const proc = Bun.spawn(cmd, { cwd, stdout: 'pipe', stderr: 'pipe', timeout: opts.timeoutMs ?? 120_000 });
  const [stdout, stderr, code] = await Promise.all([
    new Response(proc.stdout).text(),
    new Response(proc.stderr).text(),
    proc.exited,
  ]);
  return { code, stdout: stdout.trim(), stderr: stderr.trim() };
}

export async function shOk(cmd: string[], cwd: string): Promise<string> {
  const r = await sh(cmd, cwd);
  if (r.code !== 0) throw new Error(`命令失败（${r.code}）：${cmd.join(' ')}\n${r.stderr || r.stdout}`);
  return r.stdout;
}

// 需要人确认的步骤：要求输入指定的词，避免手滑回车就放行。
export function confirmByTyping(question: string, expected: string): boolean {
  const answer = prompt(`${question}\n确认请输入 ${expected}：`);
  return answer?.trim() === expected;
}

6.3 worktree：隔离与安全清理

两个细节值得注意：驾驭器的文件写进 info/exclude，这样它们不会出现在 git status 里、不会被 agent 误提交；而 git worktree remove 仍会因为这些被忽略的文件拒绝删除，所以先由我们自己核对"有没有真正的未保存工作"，归档后再强制删除。


import { appendFile, cp, mkdir } from 'node:fs/promises';
import { homedir } from 'node:os';
import { basename, join, resolve } from 'node:path';
import { sh, shOk } from './sh';
import { branchName, type CodingTask } from './task';

// worktree 放在仓库外，避免出现在仓库自己的 git status 里。
export function worktreePath(task: CodingTask): string {
  return join(homedir(), '.agent-lab', 'worktrees', basename(task.repo), task.id);
}

export async function createWorktree(task: CodingTask): Promise<string> {
  const path = worktreePath(task);
  if (await Bun.file(join(path, '.git')).exists()) return path; // 重跑时接着用
  await mkdir(join(path, '..'), { recursive: true });
  await shOk(['git', 'fetch', 'origin', task.base], task.repo);
  await shOk(['git', 'worktree', 'add', '-b', branchName(task), path, `origin/${task.base}`], task.repo);
  // 驾驭器自己的文件不进版本库：写进所有 worktree 共用的 info/exclude
  const common = resolve(path, await shOk(['git', 'rev-parse', '--git-common-dir'], path));
  await appendFile(join(common, 'info', 'exclude'), '\n/.harness/\n/.claude/settings.local.json\n');
  return path;
}

export type CleanupCheck = { ok: boolean; reasons: string[] };

// 删除前核对：有未提交改动或未推送的提交就不删，免得丢工作。
export async function checkRemovable(path: string): Promise<CleanupCheck> {
  const reasons: string[] = [];
  const status = await shOk(['git', 'status', '--porcelain'], path);
  if (status) reasons.push(`有未提交的改动：\n${status}`);
  // 不和 @{u} 比：从 origin/main 建出的分支会默认跟踪 origin/main，推送时没加 -u 就会误报。
  // 只看"有没有本地提交不在任何远端分支上"，推到哪个远端分支都算已推送。
  const unpushed = await shOk(['git', 'rev-list', '--count', 'HEAD', '--not', '--remotes'], path);
  if (Number(unpushed) > 0) reasons.push(`有 ${unpushed} 个提交没推送到任何远端分支`);
  return { ok: reasons.length === 0, reasons };
}

// 调用前必须先过 checkRemovable。剩下的只有驾驭器自己的被忽略文件（.harness/ 等），
// git 仍会因它们拒绝删除，所以先把 .harness/ 归档到运行记录目录，再强制删除。分支保留，PR 不受影响。
export async function removeWorktree(task: CodingTask): Promise<string> {
  const path = worktreePath(task);
  const archive = join(homedir(), '.agent-lab', 'runs', `${task.id}-${Date.now()}`);
  await mkdir(archive, { recursive: true });
  await cp(join(path, '.harness'), archive, { recursive: true });
  await shOk(['git', 'worktree', 'remove', '--force', path], task.repo);
  return archive;
}

6.4 功能清单：只许改 passes

Anthropic 在长任务驾驭的实践里发现：用 JSON 而不是 Markdown 记功能清单，模型更不容易随手改写；并且要明确规定 agent 只能改 passes 字段。驾驭器在每轮后核对，越权的改动恢复、合法的保留。


// 功能清单：把验收点展开成 JSON，agent 只允许改 passes 字段。
// 用 JSON 而不是 Markdown：模型更不容易随手改写 JSON 的结构和措辞。
export type Feature = { id: string; description: string; passes: boolean };

export function initFeatures(acceptance: string[]): Feature[] {
  return acceptance.map((description, i) => ({ id: `F${i + 1}`, description, passes: false }));
}

// 对比一轮前后的清单：除了 passes，任何改动（删条目、改描述、加条目）都算违规。
export function checkIntegrity(before: Feature[], after: unknown): string[] {
  if (!Array.isArray(after)) return ['features.json 不再是数组'];
  const violations: string[] = [];
  if (after.length !== before.length) violations.push(`条目数从 ${before.length} 变成了 ${after.length}`);
  before.forEach((b, i) => {
    const a = after[i] as Partial<Feature> | undefined;
    if (!a) return;
    if (a.id !== b.id) violations.push(`第 ${i + 1} 条的 id 被改成了 ${String(a.id)}`);
    if (a.description !== b.description) violations.push(`${b.id} 的描述被改动`);
    if (typeof a.passes !== 'boolean') violations.push(`${b.id} 的 passes 不是布尔值`);
    const extra = Object.keys(a).filter((k) => !['id', 'description', 'passes'].includes(k));
    if (extra.length) violations.push(`${b.id} 多了字段：${extra.join('、')}`);
  });
  return violations;
}

// 合法的那部分改动（passes）保留，其余恢复原样。
export function repair(before: Feature[], after: unknown): Feature[] {
  const list = Array.isArray(after) ? (after as Array<Partial<Feature>>) : [];
  return before.map((b) => {
    const a = list.find((x) => x?.id === b.id);
    return { ...b, passes: typeof a?.passes === 'boolean' ? a.passes : b.passes };
  });
}

export function allPass(features: Feature[]): boolean {
  return features.every((f) => f.passes);
}

6.5 客观进度：读 git 与 gh

agent 说"我已经提交并开了 PR"不等于真的做了。驾驭器每轮结束自己看：


import { sh } from './sh';

// 客观进度：不听 agent 自己说做到哪了，直接读 git 和 gh。
export type CiState = 'none' | 'pending' | 'success' | 'failure';
export type Snapshot = {
  dirty: string[];
  commits: string[];
  unpushed: number; // 不在任何远端分支上的本地提交数
  pr: { url: string; state: string } | null;
  ci: CiState;
};

type Check = { __typename?: string; status?: string; conclusion?: string | null; state?: string };

// gh 的 statusCheckRollup 里混着两种记录：CheckRun（status + conclusion）与 StatusContext（state）。
export function classifyChecks(checks: Check[]): CiState {
  if (checks.length === 0) return 'none';
  const BAD = ['FAILURE', 'ERROR', 'CANCELLED', 'TIMED_OUT', 'ACTION_REQUIRED', 'STARTUP_FAILURE'];
  const results = checks.map((c) => {
    if (c.__typename === 'StatusContext' || (c.state && !c.status)) {
      const s = (c.state ?? '').toUpperCase();
      return BAD.includes(s) ? 'failure' : s === 'SUCCESS' ? 'success' : 'pending';
    }
    if ((c.status ?? '').toUpperCase() !== 'COMPLETED') return 'pending';
    const conclusion = (c.conclusion ?? '').toUpperCase();
    return BAD.includes(conclusion) ? 'failure' : 'success'; // SUCCESS、NEUTRAL、SKIPPED 都不挡路
  });
  if (results.includes('failure')) return 'failure';
  if (results.includes('pending')) return 'pending';
  return 'success';
}

export async function snapshot(path: string, base: string): Promise<Snapshot> {
  const status = await sh(['git', 'status', '--porcelain'], path);
  const log = await sh(['git', 'log', '--oneline', `origin/${base}..HEAD`], path);
  // 不和 @{u} 比：从 origin/main 建出的分支默认跟踪 origin/main，推送时没加 -u 会把已推送的提交也算进来
  const ahead = await sh(['git', 'rev-list', '--count', 'HEAD', '--not', '--remotes'], path);
  const pr = await sh(['gh', 'pr', 'view', '--json', 'url,state,statusCheckRollup'], path);
  let prInfo: Snapshot['pr'] = null;
  let ci: CiState = 'none';
  if (pr.code === 0) {
    const data = JSON.parse(pr.stdout) as { url: string; state: string; statusCheckRollup: Check[] | null };
    prInfo = { url: data.url, state: data.state };
    ci = classifyChecks(data.statusCheckRollup ?? []);
  }
  return {
    dirty: status.stdout ? status.stdout.split('\n') : [],
    commits: log.stdout ? log.stdout.split('\n') : [],
    unpushed: ahead.code === 0 ? Number(ahead.stdout) : 0,
    pr: prInfo,
    ci,
  };
}

export function describe(s: Snapshot): string {
  return [
    `未提交 ${s.dirty.length} 个文件`,
    `新提交 ${s.commits.length} 个`,
    `待推送 ${s.unpushed}`,
    s.pr ? `PR ${s.pr.state} ${s.pr.url}` : '无 PR',
    `CI ${s.ci}`,
  ].join(' · ');
}

6.6 启动 agent 与解析事件流

print 模式下用 --output-format stream-json 拿到逐行 JSON 事件：初始化事件带会话 id，助手消息里有工具调用，最后的结果事件带 total_cost_usd。驾驭器用它显示进度、累计成本、触发预算刹车。权限上只放行列出的命令，文件编辑用 acceptEdits 自动接受。


// 以 headless 方式启动编码 agent，并把它的事件流变成驾驭器能用的信息。
// 命令行参数与事件字段以各自的官方文档为准；解析器对不认识的事件只记录、不报错。
export type AgentKind = 'claude' | 'codex';

export function buildCommand(kind: AgentKind, prompt: string): string[] {
  if (kind === 'claude') {
    return [
      'claude', '-p', prompt,
      '--output-format', 'stream-json', '--verbose', // 逐行 JSON 事件；print 模式下流式输出需要 --verbose
      '--permission-mode', 'acceptEdits',            // 允许改文件；其余命令按下面的白名单放行
      '--allowedTools', 'Bash(bun test:*)', 'Bash(bun run:*)', 'Bash(git status:*)', 'Bash(git diff:*)',
      'Bash(git add:*)', 'Bash(git commit:*)', 'Bash(git push:*)', 'Bash(gh pr create:*)', 'Bash(gh pr view:*)',
    ];
  }
  // Codex：默认只读沙箱，workspace-write 允许写工作区；--json 输出 JSONL 事件
  return ['codex', 'exec', '--json', '--sandbox', 'workspace-write', prompt];
}

export type AgentEvent = {
  kind: 'init' | 'text' | 'tool' | 'result' | 'other';
  sessionId?: string;
  text?: string;
  tool?: string;
  costUsd?: number;
  isError?: boolean;
  raw: unknown;
};

type ContentBlock = { type?: string; text?: string; name?: string };

export function parseEventLine(line: string): AgentEvent | null {
  if (!line.trim()) return null;
  let e: Record<string, unknown>;
  try {
    e = JSON.parse(line) as Record<string, unknown>;
  } catch {
    return { kind: 'other', text: line, raw: line }; // 非 JSON 行（例如警告）原样记下
  }
  const sessionId = typeof e.session_id === 'string' ? e.session_id : undefined;
  if (e.type === 'system' && e.subtype === 'init') return { kind: 'init', sessionId, raw: e };
  if (e.type === 'assistant') {
    const blocks = ((e.message as { content?: ContentBlock[] } | undefined)?.content ?? []) as ContentBlock[];
    const tool = blocks.find((b) => b.type === 'tool_use');
    if (tool) return { kind: 'tool', tool: tool.name, sessionId, raw: e };
    const text = blocks.filter((b) => b.type === 'text').map((b) => b.text ?? '').join('');
    return { kind: 'text', text, sessionId, raw: e };
  }
  if (e.type === 'result') {
    return {
      kind: 'result',
      sessionId,
      text: typeof e.result === 'string' ? e.result : undefined,
      costUsd: typeof e.total_cost_usd === 'number' ? e.total_cost_usd : undefined,
      isError: e.is_error === true || (typeof e.subtype === 'string' && e.subtype !== 'success'),
      raw: e,
    };
  }
  return { kind: 'other', raw: e };
}

export type SessionOutcome = { exitCode: number; sessionId: string | null; costUsd: number; finalText: string; tools: number };

export async function runSession(
  kind: AgentKind,
  cwd: string,
  prompt: string,
  onEvent: (e: AgentEvent) => void,
  timeoutMs = 45 * 60_000,
): Promise<SessionOutcome> {
  const proc = Bun.spawn(buildCommand(kind, prompt), { cwd, stdout: 'pipe', stderr: 'inherit', timeout: timeoutMs });
  const out: SessionOutcome = { exitCode: -1, sessionId: null, costUsd: 0, finalText: '', tools: 0 };
  const decoder = new TextDecoder();
  let buf = '';
  for await (const chunk of proc.stdout) {
    buf += decoder.decode(chunk, { stream: true });
    let nl = buf.indexOf('\n');
    while (nl >= 0) {
      const e = parseEventLine(buf.slice(0, nl));
      buf = buf.slice(nl + 1);
      nl = buf.indexOf('\n');
      if (!e) continue;
      if (e.sessionId) out.sessionId = e.sessionId;
      if (e.kind === 'tool') out.tools++;
      if (e.kind === 'result') {
        out.costUsd = e.costUsd ?? 0;
        out.finalText = e.text ?? '';
      }
      onEvent(e);
    }
  }
  out.exitCode = await proc.exited;
  return out;
}
换成 Codex

codex exec 默认在只读沙箱里运行，--sandbox workspace-write 允许写工作区；--json 输出 JSONL 事件，--output-schema 可以约束最终输出，codex exec resume 用来续跑。它的事件字段与 Claude Code 不同，本页的解析器会把不认识的事件归为 other 并照常记录；成本需要按事件里的 token 用量自己估算。Codex 没有 Claude Code 的 Stop hook，"停下前检查未提交改动"要改由驾驭器在轮后核对时追加一轮来完成。

6.7 Stop hook：别带着未保存的改动停下

Claude Code 的 Stop hook 在 agent 准备停下时运行。退出码 2 才会阻止停止（退出码 1 不会，这是常见陷阱），stderr 的内容交回给 agent。输入里的 stop_hook_active 表示"已经因为 Stop hook 续跑过"，此时必须放行，否则可能无限循环（系统另有连续续跑次数的上限）。


// Claude Code 的 Stop hook：agent 想停下时运行。
// 有未提交改动 → 退出码 2，stderr 的内容会交回给 agent，它会继续干活；只提醒一次。
// 注意：退出码 1 不会阻止停止，只有 2 才会。
export type HookInput = { stop_hook_active?: boolean; cwd?: string };

export function decide(input: HookInput, dirtyFiles: string[]): { code: 0 | 2; message: string } {
  // 已经因为 Stop hook 继续过一次了：放行，避免无限循环
  if (input.stop_hook_active) return { code: 0, message: '' };
  if (dirtyFiles.length === 0) return { code: 0, message: '' };
  return {
    code: 2,
    message: [
      `停下之前还有 ${dirtyFiles.length} 个文件的改动没有提交：`,
      ...dirtyFiles.slice(0, 20),
      '请确认这些改动是否属于本次功能：属于就运行测试后提交，并更新 .harness/progress.md；不属于就还原。',
    ].join('\n'),
  };
}

if (import.meta.main) {
  const input = JSON.parse(await Bun.stdin.text()) as HookInput;
  const proc = Bun.spawnSync(['git', 'status', '--porcelain'], { cwd: input.cwd ?? process.cwd() });
  const dirty = proc.stdout.toString().split('\n').filter((l) => l.trim() && !l.includes('.harness/'));
  const { code, message } = decide(input, dirty);
  if (message) console.error(message);
  process.exit(code);
}

驾驭器在 worktree 里写一份 .claude/settings.local.json 注册它（见 6.9 的 main.ts），格式以官方 hooks 文档为准：


{
  "hooks": {
    "Stop": [{ "hooks": [{ "type": "command", "command": "bun /abs/path/agent-lab/harness/stop-hook.ts" }] }]
  }

6.8 每轮的提示词

提示词的核心是一套固定的"开工流程"：先确认自己在哪、读进度和历史、挑一个功能、做完验证、只改 passes、提交、写进度。遇到需要人决定的事就写下来停下，而不是猜。


import type { CodingTask } from './task';

// 每一轮都是全新的上下文，状态全靠仓库里的文件传递：功能清单、进度文件、git 历史。
export function sessionPrompt(task: CodingTask, session: number): string {
  return `你在为任务「${task.title}」工作，这是第 ${session} 轮。你的上下文是全新的，先按顺序做：
1. 运行 pwd，阅读 .harness/progress.md 和 git log --oneline -20，了解之前做到哪。
2. 阅读 .harness/features.json，选出一条 passes 为 false 的功能，这一轮只做这一条。
3. 实现它，并运行 ${task.verify.join(' ')} 验证；需要端到端检查的，按功能描述实际操作一遍，不要只看单元测试。
4. 确认通过后，把这一条的 passes 改为 true。features.json 里除 passes 外的任何内容都不许改、不许删条目。
5. 提交改动（一个功能一个提交），推送分支；还没有 PR 时用 gh pr create 开一个草稿 PR。
6. 在 .harness/progress.md 末尾追加：本轮做了什么、怎么验证的、下一轮该注意什么。
如果遇到无法独立决定的问题（需求有歧义、需要密钥、需要改与任务无关的代码），把问题写进 progress.md 的"待人决定"一节后停下，不要猜。`;
}

export function initialProgress(task: CodingTask): string {
  return `# ${task.title}\n\n任务 ID：${task.id}\n基线分支：${task.base}\n\n## 验收点\n${task.acceptance.map((a, i) => `- F${i + 1}：${a}`).join('\n')}\n\n## 待人决定\n\n（无）\n\n## 进度记录\n`;
}

6.9 生命周期编排


// 用法：bun harness/main.ts tasks/export-filter.json
import { appendFile, mkdir } from 'node:fs/promises';
import { join, resolve } from 'node:path';
import { runSession } from './agent';
import { allPass, checkIntegrity, type Feature, initFeatures, repair } from './features';
import { describe, snapshot } from './progress';
import { initialProgress, sessionPrompt } from './prompts';
import { confirmByTyping, sh } from './sh';
import { branchName, loadTask } from './task';
import { checkRemovable, createWorktree, removeWorktree, worktreePath } from './worktree';

const taskFile = process.argv[2];
if (!taskFile) throw new Error('用法：bun harness/main.ts <任务文件.json>');
const task = await loadTask(taskFile);

// ---- 1. 人确认后才启动 ----
console.log(`任务：${task.title}\n仓库：${task.repo}（基于 ${task.base}，新分支 ${branchName(task)}）`);
console.log(`工作目录：${worktreePath(task)}\n执行方：${task.agent}，最多 ${task.maxSessions} 轮，预算 $${task.maxCostUsd}`);
console.log(`验收点：\n${task.acceptance.map((a, i) => `  F${i + 1}. ${a}`).join('\n')}`);
if (!confirmByTyping('确认启动？', task.id)) process.exit(0);

// ---- 2. 隔离的工作目录与驾驭文件 ----
const wt = await createWorktree(task);
const dir = join(wt, '.harness');
await mkdir(dir, { recursive: true });
const featuresFile = Bun.file(join(dir, 'features.json'));
if (!(await featuresFile.exists())) {
  await Bun.write(featuresFile, `${JSON.stringify(initFeatures(task.acceptance), null, 2)}\n`);
  await Bun.write(join(dir, 'progress.md'), initialProgress(task));
}
if (task.agent === 'claude') {
  const hook = `bun ${resolve(import.meta.dir, 'stop-hook.ts')}`;
  await mkdir(join(wt, '.claude'), { recursive: true });
  await Bun.write(join(wt, '.claude', 'settings.local.json'), JSON.stringify({ hooks: { Stop: [{ hooks: [{ type: 'command', command: hook }] }] } }, null, 2));
}
const events = join(dir, 'events.jsonl');
const record = (type: string, data: Record<string, unknown>) =>
  appendFile(events, `${JSON.stringify({ ts: new Date().toISOString(), type, ...data })}\n`);

// ---- 3. 逐轮推进：每轮一个全新上下文，只做一个功能 ----
let spent = 0;
let stalled = 0;
for (let session = 1; session <= task.maxSessions; session++) {
  const before = (await featuresFile.json()) as Feature[];
  if (allPass(before)) break;
  const commitsBefore = (await snapshot(wt, task.base)).commits.length;
  console.log(`\n== 第 ${session} 轮 ==`);
  const outcome = await runSession(task.agent, wt, sessionPrompt(task, session), (e) => {
    if (e.kind === 'tool') console.log(`  · ${e.tool}`);
    void record('agent', { session, kind: e.kind, tool: e.tool, text: e.text?.slice(0, 500) });
  });
  spent += outcome.costUsd;

  // 功能清单只许改 passes：越权的改动恢复，合法的保留
  const after: unknown = await featuresFile.json().catch(() => null);
  const violations = checkIntegrity(before, after);
  if (violations.length) {
    await Bun.write(featuresFile, `${JSON.stringify(repair(before, after), null, 2)}\n`);
    await record('violation', { session, violations });
    console.warn(`  ! 功能清单被越权修改，已恢复：${violations.join('；')}`);
  }
  const snap = await snapshot(wt, task.base);
  const features = (await featuresFile.json()) as Feature[];
  await record('session', { session, exitCode: outcome.exitCode, costUsd: outcome.costUsd, sessionId: outcome.sessionId, snapshot: snap });
  console.log(`  ${describe(snap)} · 功能 ${features.filter((f) => f.passes).length}/${features.length} · 累计 $${spent.toFixed(2)}`);

  // 刹车：超预算、连续两轮没有任何新提交
  if (spent >= task.maxCostUsd) {
    console.warn('已达预算上限，停止。');
    break;
  }
  stalled = snap.commits.length > commitsBefore ? 0 : stalled + 1;
  if (stalled >= 2) {
    console.warn('连续两轮没有新提交，停下等人看 .harness/progress.md 的"待人决定"。');
    break;
  }
}

// ---- 4. 独立复核：不采信 agent 的自述 ----
const features = (await featuresFile.json()) as Feature[];
const verify = await sh(task.verify, wt, { timeoutMs: 15 * 60_000 });
const snap = await snapshot(wt, task.base);
console.log('\n== 复核 ==');
for (const f of features) console.log(`  ${f.passes ? '✓' : '✗'} ${f.id} ${f.description}`);
console.log(`  复核命令 ${task.verify.join(' ')}：${verify.code === 0 ? '通过' : `失败（${verify.code}）`}`);
console.log(`  ${describe(snap)}`);
const done = allPass(features) && verify.code === 0 && snap.dirty.length === 0 && snap.ci !== 'failure';
await record('verify', { done, verifyCode: verify.code, snapshot: snap, spent });
console.log(done ? '\n结论：可以交给人评审 PR。' : '\n结论：还不能交付，见上面未通过的项。');

// ---- 5. 收尾清理（需确认，且有未保存的工作时拒绝） ----
if (done && confirmByTyping('删除工作目录？分支与 PR 保留。', 'remove')) {
  const check = await checkRemovable(wt);
  if (!check.ok) console.warn(`不删除：\n${check.reasons.join('\n')}`);
  else {
    const archive = await removeWorktree(task);
    console.log(`已删除工作目录；功能清单、进度与事件记录归档在 ${archive}`);
  }
}

agent 在第 3 轮结束时说"所有功能都已完成并通过测试"，features.json 也全部是 passes: true。驾驭器接下来应该？

  1. 相信它，直接通知人合并
  2. 再开一轮，让 agent 自己检查一遍
  3. 看 agent 输出里有没有"测试通过"字样
  4. 由驾驭器自己运行复核命令、检查工作区是否干净与 CI 状态，全部满足才交给人评审
"过早宣布完成"是长任务的头号失败。passes 是 agent 自己改的，"测试通过"是 agent 自己说的。驾驭器要用自己能验证的事实（复核命令的退出码、git 状态、CI）做结论；最终的合并决定仍然留给人。

8 · 验收标准

  • bun test 全部通过，包括在临时仓库里实跑 Stop hook 的测试
  • 在练习仓库上用一个 2–3 条验收点的任务跑通全流程：开出 PR、CI 通过、复核结论为可交付
  • 手动在 worktree 里留一个未提交文件后让 agent 停下，观察到 Stop hook 阻止了一次、第二次放行
  • 手动改坏 features.json 的描述，下一轮结束后被检测并恢复，事件记录里有违规条目
  • 把预算设得很低，确认驾驭器在超预算后停下
  • 收尾时故意留一个未推送的提交，清理被拒绝；推送后清理成功，.harness/ 已归档
  • 同时开两个任务并行运行，两个 worktree 互不影响

9 · 进阶挑战

  1. 接回审批流：把"确认启动"和"确认清理"改成 P3 的提案，可以在别处审批；驾驭器崩溃重启后从事件记录恢复到正确的阶段。
  2. 独立评审者：所有功能通过后，用一个全新上下文、只读权限的 agent 按验收点逐条审查 diff，结论写回进度文件（评估者与生成者分离，参见第 12 章）。
  3. 跟进 CI 与评审意见：PR 的 CI 失败或出现新的评审意见时，自动开一轮，把失败日志或评审意见作为本轮输入。
  4. 可替换的执行方：把 agent.ts 抽象成接口，实现 Claude 与 Codex 两个适配器，用 P6 的方法在同一批小任务上比较两者的通过率与成本。
  5. 中途交接：实现"换 agent 接手"：新 agent 的首轮提示里带上原始需求、分支、最近的进度与事件，要求先核对 git status 再继续。

10 · 常见坑

  • 一次做完整个需求：上下文中途耗尽，留下半成品。坚持每轮一个功能、每个功能一个提交。
  • 相信 agent 的自述：进度看 git 与 gh，完成看独立复核。
  • Stop hook 用退出码 1：不会阻止停止。要阻止用 2；并处理 stop_hook_active 防死循环。
  • 驾驭文件进了版本库：.harness/ 与 settings.local.json 写进 info/exclude。
  • 清理时丢工作：先核对未提交与未推送，再归档，最后删除；分支永远保留。
  • 权限给太宽：无人值守时只放行任务需要的命令；不要为了省事跳过所有权限检查。
  • 没有刹车：轮数、预算、停滞三道刹车缺一不可，否则一个卡住的任务能整晚空转。
本项目要点
  • 驾驭器负责"在哪跑、能动什么、做到哪、何时算完"，agent 只负责写代码。
  • 每轮全新上下文、只做一个功能，状态靠功能清单、进度文件和 git 历史传递。
  • 功能清单用 JSON，只许改 passes；每轮后核对，越权改动恢复。
  • 进度读 git 与 gh；完成由驾驭器独立复核；Stop hook 用退出码 2 并防死循环。
  • 启动与清理是需要人确认的动作；清理前核对、归档，分支与 PR 留给人评审。
