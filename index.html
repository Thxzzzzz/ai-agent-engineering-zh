这门课要把你带到哪里

一个高级 Agent 工程师和"能写出 demo 的人"之间的差距，几乎都不在提示词上，而在这些问题上：

它为什么这样做？能读懂 trace，定位是上下文缺了、工具描述含糊，还是模型能力边界。
它会不会闯祸？知道提示注入怎么发生，用架构而不是祈祷来限制后果；高风险动作必须经人审批。
它挂了会怎样？进程崩溃、网络抖动、模型超时之后，不重发、不丢单、能从断点继续。
它是变好还是变差？有评测集、有回归、有线上指标，改一句提示词前后能拿数字说话。
它值不值这个钱？算得清 token、缓存命中和模型分级，知道延迟花在了哪里。
它该做多大？知道什么时候用一次调用、什么时候用 workflow、什么时候才需要 agent 或多 agent。

学习路线

怎么用这门课

  1. 按顺序读，但别只读。每章都有分步动画（点"下一步"）、交互组件和小测。小测答错了不要紧，解释比答案重要。
  2. 每部分做一个跟练项目。项目用 TypeScript（Bun 运行时），从 100 行的最小 agent 一路长成带审批、记忆、评测和可观测的系统。所有项目都能用"假模型"离线跑测试，真实模型只在最后接入。
  3. 对照真实项目复盘。每章末尾的"真实项目复盘"提示框，指向两个真实项目里因缺少这块知识而走的弯路；第五部分的复盘章把 31 条发现汇总成热力图、根因分析和整改清单。
  4. 读名作的源码。第六部分研读 Claude Code、Codex CLI、Gemini CLI、OpenHands、SWE-agent、Aider、Letta、LangGraph、goose，每篇固定到具体提交，并和课程章节、复盘条目对照。
  5. 用能力自测检验自己。附录里的清单列出了高级 Agent 工程师应当能独立完成的事；勾不上的条目，回到对应章节。
  6. 读一手资料。每章末尾列出原始出处（官方博客、规范、论文）。这个领域变化很快，课程内容截至 2026 年 11 月核实过，之后请以原文为准。
